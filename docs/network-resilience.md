# 弱网操作与恢复

保留 WebSocket/Protobuf、服务端回合令牌及 Redis 原子提交。客户端一次只提交一个游戏操作，不排队、不自动重发。离线发送明确显示“未发送”；提交后等待带相同回合令牌的服务端广播。确认超时（10 秒）或连接失效时，保留待核对状态并重连。

每个玩家最近一次成功提交的令牌与牌局一起持久化，并随该玩家的重连快照返回。回执只在同一 Redis 提交成功后可见；写入成功但响应丢失时仍可恢复。自动超时操作不冒充玩家提交的回执。旧客户端可忽略新增的 Protobuf 字段。

心跳每 5 秒一次，15 秒无 pong 或握手未完成则重建连接。重试间隔从 2.5 秒指数增长至 15 秒；身份和快照恢复后复位。后台恢复及 online 事件主动检测。被其他页面替换的连接不自动重连。

显示与提醒共用绝对截止时间。ping/pong 中点估计校准服务器时差，后续 RTT 样本也校正当前回合。首次采样前使用服务器消息中的时间；网络路径不对称时中点估计仍有误差，最终能否操作始终由服务端决定。

带 Vite 八位哈希且实际存在的 /assets 文件使用一年 immutable 缓存；入口和非哈希文件继续重新验证，API 保持 no-store。

验证分层：Go race 测试覆盖重复请求、Redis 提交响应丢失和快照恢复；Vitest 注入 500/1000/2000ms 延迟、1%/5% 心跳响应丢失、半开连接、提交中断线及 online/后台恢复；Playwright 只保留页面可启动和基础操作可见的冒烟测试。响应丢失是应用层故障注入，不等同于真实网络接口的随机 TCP 丢包；真实移动网络及非对称链路仍需部署环境验收。
