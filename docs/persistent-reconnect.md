# 第一阶段：持久身份与断线续局

> 本文记录一期设计。当前服务已加入[二期重启恢复](restart-recovery.md)，重启边界、Redis 故障处理与战绩补写以二期文档为准。

## 交付边界

游客身份、昵称、凭据哈希和已写入的战绩存放 Redis。Redis 数据卷需持久化（Compose 已启用 AOF）。浏览器刷新、关闭页面再打开均使用同一个持久 HttpOnly Cookie。服务重启后可恢复身份和战绩，但不恢复原牌局；房间、手牌、计时器和待补发结算仍只存在当前服务进程中。

本阶段按单服务器实例运行，不提供跨实例的牌局同步或连接互斥。

## 时间与离线策略

| 配置 / 环境变量 | 默认 | 含义 |
| --- | --- | --- |
| `server.identity_ttl` / `IDENTITY_TTL` | 2592000 秒（30 天） | 身份与 Cookie 的固定有效期；验证不会延长有效期 |
| `game.offline_wait_timeout` / `GAME_OFFLINE_WAIT_TIMEOUT` | 30 秒 | 当前操作玩家断线时暂停其回合计时，等待重连；到期自动叫牌/出牌，后续按正常回合超时托管 |
| `game.offline_room_retention` / `GAME_OFFLINE_ROOM_RETENTION` | 600 秒 | 所有真人离线后，房间最多保留多久；机器人不算在线真人 |
| `game.result_retention` / `GAME_RESULT_RETENTION` | 120 秒 | 牌局结束后保留快照和结算多久，从结束时间开始计算 |
| `game.room_timeout` / `GAME_ROOM_TIMEOUT` | 10 分钟 | 原有等待开局房间的有效期 |

超出重连等待时间不会使身份失效。只要原局仍存活，托管后也可回来接管。全员离线时沿用托管，不无限暂停；任一真人在保留期内回来会取消本次全员离线回收倒计时。再次全部离线则重新计时。等待房间同时受等待开局期限约束。

清理任务每秒回收一次过期房间，并停止发牌、回合和机器人任务。重连入口也检查期限，不能利用清理间隔恢复已过期的局。若托管在回收前结束牌局，则转入独立的结算保留期。结算关联与活动房间分开：看到结果后可以开新局；下一次重连优先恢复新局，不会被旧结算拉回去。

## 认证与多连接

- 浏览器握手由服务端读取 `ddz_guest` Cookie，通过 Redis 验证 ID 和 256 位随机凭据。Redis 只保存 SHA-256 哈希，不保存明文凭据。
- Cookie 使用 `HttpOnly`、`SameSite=Strict`、`Path=/`、`Max-Age` 和 `Expires`；JavaScript 不读取、不持久化凭据。旧版 `sessionStorage` 令牌会被移除。部署升级不会将旧内存游客自动迁移为新身份。
- HTTPS 直连自动使用 `Secure`。TLS 在代理终止时必须配置 `COOKIE_SECURE=true`，并设置 `SECURITY_ALLOWED_ORIGINS=https://实际公网域名`。多个 Origin 用逗号分隔。代理应保留正确 Host，或显式列出对外 Origin；不根据客户端提交的转发头推断可信来源。
- 默认允许同源 WebSocket 和无 Origin 的终端连接。跨域浏览器只允许显式列出的完整 Origin（协议、主机、端口）；`*` 不会开放跨域。
- 终端继续使用 `Connected.reconnect_token` 与原有 `Reconnect` 消息；服务端通过 Redis 验证。终端重连期间不会用临时连接消息覆盖旧凭据。浏览器不接收令牌，也不能通过 `Reconnect` 消息切换身份。
- 同一身份新连接替换旧连接，旧连接收到关闭码 `4001`，停止自动重连。旧连接的消息、延迟断线回调和待执行匹配不能影响新连接或另建一局。正在游戏时不能创建/加入其他局。
- 状态变更、连接替换和断线保持互斥。只读的统计与排行榜请求在短临界区内确认连接有效后，释放连接锁再查询 Redis；两类查询各有 2 秒总超时，单个慢查询不阻塞其他玩家的操作或重连。

## 恢复内容与隐私

重连复用已有 `Reconnected`、当前回合通知和 `GameOver` 流程。快照包含玩家座位/在线状态、本人当前手牌、阶段、公开底牌、当前倍数、完整公开出牌/不出记录、上一手牌型、发牌时间、服务器时间、回合截止时间和暂停状态。前端重建记牌器、桌面当前轮出牌和最近记录；终端也恢复倍数和记牌器。

进行中的快照不发送其他玩家手牌；叫地主和发牌阶段不发送真实底牌。历史只来自已接受的公开操作，不复用包含私有手牌的训练记录。结束后沿用现有结算规则展示剩余手牌。

## Redis 故障

新连接和重连必须通过 Redis。Redis 出错时浏览器握手返回 503，不覆盖 Cookie、不注销正在使用的身份、不降级成内存游客；网络恢复后重试原 Cookie。过期或无效凭据会创建新的游客身份。

已连接的牌局在内存中继续运行。结算消息不依赖战绩写入成功；战绩写入使用 Redis 事务，同时更新统计、排行榜和去重标记。释放玩家席位前，结果先进入该玩家按牌局完成顺序处理的进程内队列；首次写入和重试共用队列，新局不会越过尚未写入的旧局，从而保留积分下限和连胜计算的顺序。不同玩家的队列独立执行，重复结果不会重复计分。

短暂失败后每 2 秒重试，每条结果从入队起最多保留 10 分钟。Redis 持续不可用超过此窗口，或待写结果落盘前服务进程退出，未写入的战绩无法保证保留，日志会记录失败。这阶段不提供跨进程待写队列或原局恢复。
